# Требования к системе

## User Stories

### US-01. Ответ на вопрос по корпоративным регламентам
**Как** сотрудник компании,  
**я хочу** задать вопрос и получить понятный ответ со ссылками на регламенты,  
**чтобы** быстро найти нужную информацию без долгого ручного чтения сотен страниц документов.

**Критерии приёмки:**
- Ответ формируется только на базе найденных корпоративных документов;
- В теле ответа указаны кликабельные ссылки или названия документов-источников;
- Если информации нет в базе знаний, ассистент прямо сообщает: «В документации компании нет информации по данному вопросу».

---

### US-02. Загрузка нового документа
**Как** администратор базы знаний,  
**я хочу** загрузить новый файл документации в формате Markdown или PDF,  
**чтобы** актуальная информация сразу стала доступна для поиска через RAG-агента.

**Критерии приёмки:**
- Система загружает формат файла и успешно его парсит;
- Документ нарезается на чанки и векторизуется с сохранением в векторную базу;
- Пользователю отображается статус: «Документ успешно загружен».

---

### US-03. Оценка релевантности ответа
**Как** пользователь,  
**я хочу** поставить отметку «полезно / не помогло» под сгенерированным ответом,  
**чтобы** команда проекта могла улучшать точность поиска и качество ответов модели.

**Критерии приёмки:**
- Под каждым ответом доступны кнопки положительной и отрицательной оценки;
- При нажатии «не помогло» можно оставить текстовый комментарий с причиной;
- Оценка вместе с историей диалога сохраняется в сервисе аналитики.

## Use Case

### UC-01. Запрос информации по корпоративным регламентам

- **Актор:** Сотрудник компании.
- **Цель:** Получить достоверный ответ на рабочий вопрос с указанием источников.
- **Предусловие:** База документов предварительно загружена в БД.

**Основной сценарий:**
1. Сотрудник вводит вопрос в интерфейсе чата.
2. Система обрабатывает вопрос и выполняет поиск по базе документов.
3. LLM генерирует ответ со ссылками на источники.
4. Система отправляет ответ пользователю и отображает его в интерфейсе с указанием ссылок на документы.

**Альтернативный сценарий:**
- *Информация не найдена:* Если модель не может найти ответ в загруженных документах, то система возвращает ответ: «Информация по вашему запросу не найдена в базе знаний.

**Результат:** Сотрудник получил подтверждённый ответ со ссылкой на документ либо уведомление об отсутствии информации.
